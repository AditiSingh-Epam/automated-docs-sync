# GitHub Copilot Agent Instructions

This repository uses custom GitHub Copilot Agents for an Agentic SDLC pipeline. These agents guide the software development lifecycle from requirements through deployment.

## Available Agents

### 1. Requirements Agent
**Invocation:** `@requirements-agent`

**Purpose:** Collaboratively define functional and non-functional requirements from a user story.

**Usage:**
```
@requirements-agent
I have a user story: [paste your story]
Please help me define comprehensive requirements.
```

**Output:** `requirements.md`

**Next Agent:** Architect Agent

---

### 2. Architect Agent
**Invocation:** `@architect-agent` (Coming after Step 1)

**Purpose:** Design high-level system architecture based on approved requirements.

**Input:** `requirements.md`

**Output:** `architecture.md`

---

### 3. Design Review Agent
**Invocation:** `@design-review-agent` (Coming after Step 2)

**Purpose:** Conduct structured design review of architecture.

**Input:** `architecture.md`, `requirements.md`

**Output:** `design-review.md`

---

### 4. Planning Agent
**Invocation:** `@planning-agent` (Coming after Step 3)

**Purpose:** Break architecture into prioritized, dependency-ordered task list.

**Input:** `architecture.md`, `design-review.md`

**Output:** `impl-plan.md`

---

### 5. Implementation Agent
**Invocation:** `@implementation-agent` (Coming after Step 4)

**Purpose:** Generate source code based on approved implementation plan.

**Input:** `impl-plan.md`, `architecture.md`, `requirements.md`

**Output:** Source code files

---

### 6. Code Review Agent
**Invocation:** `@code-review-agent` (Coming after Step 5)

**Purpose:** Perform structured code review before PR creation.

**Input:** Generated source code

**Output:** `code-review.md`, review checklist

---

### 7. Verification Agent
**Invocation:** `@verification-agent` (Coming after Step 6)

**Purpose:** Generate and run comprehensive test suite and verification.

**Input:** Source code, `requirements.md`

**Output:** Test files, `verification-report.md`

---

### 8. PR Agent
**Invocation:** `@pr-agent` (Coming after Step 7)

**Purpose:** Create pull request with description, changelog, and checklist.

**Input:** All previous documents and source code

**Output:** Pull Request (formatted for GitHub)

---

## SDLC Pipeline Flow

```
User Story (JIRA/Confluence/Word)
         ↓
   @requirements-agent  → requirements.md
         ↓
   @architect-agent  → architecture.md
         ↓
   @design-review-agent  → design-review.md
         ↓
   @planning-agent  → impl-plan.md
         ↓
   HUMAN APPROVAL / HITL
         ↓
   @implementation-agent  → Source Code
         ↓
   @code-review-agent  → code-review.md
         ↓
   @verification-agent  → tests + verification-report.md
         ↓
   @pr-agent  → Pull Request
         ↓
   HUMAN REVIEW
         ↓
   MERGE TO MAIN
```

## How to Use These Agents

### Step 1: Start with Requirements Agent

1. Open GitHub Copilot Chat
2. Type: `@requirements-agent`
3. Paste your user story
4. Answer the agent's clarifying questions
5. Approve the generated `requirements.md`
6. Move to next agent

### General Pattern

Each agent:
- ✅ Accepts input from previous phase
- ✅ Asks clarifying questions (when needed)
- ✅ Generates comprehensive output document
- ✅ Provides handoff instructions to next agent

## Configuration

These agents use GitHub Copilot's built-in capabilities:
- Chat interface for interaction
- Knowledge of project context (files, code)
- Ability to generate structured content
- Integration with editor for file creation

**No external tools or dependencies required.**

## Tips for Success

1. **Be Specific:** When pasting user stories, include all context
2. **Answer Thoroughly:** Give detailed answers to clarifying questions
3. **Review Carefully:** Review agent outputs before moving to next step
4. **Human-in-the-Loop:** Approve or request changes before proceeding
5. **Document Everything:** Keep all output files in version control
